# LanNav

服务端渲染的个人导航页。一个 Go 二进制 + 一份 JSON 数据，无依赖、无 npm、无打包器。
主题文件（HTML/CSS/JS）编译进二进制，部署时只要拷两样东西。

```powershell
go build -o lannav.exe . ; .\lannav.exe     # http://localhost:7865
.\lannav.exe -theme mytheme              # 换主题
.\lannav.exe -port 9000 -data x.json     # 换端口 / 换数据文件（默认 data/data.json）
.\lannav.exe -bind 127.0.0.1             # 只给本机用：不监听网卡，防火墙不弹窗，节点应答也一并关掉
```

导航页在 `/`，编辑书签在 `/admin`。

**Windows 上别用 `go run .`。** 服务监听所有网卡，第一次启动 Windows 防火墙会弹窗问「允许访问」，
放行规则按 exe 的完整路径记。`go run` 每次都编译到 `%TEMP%\go-build<随机数>\…\lannav.exe`，
路径次次不同，防火墙就次次当成新程序再问一遍，「允许的应用」里还会越堆越多。
编译到固定的 `lannav.exe` 再运行，允许一次就够了；改了 Go 代码重新 `go build` 覆盖同一个文件即可。
（Linux / macOS 没这回事，`go run .` 随便用。）

两种办法可以彻底不弹：开发时只在本机看，加 `-bind 127.0.0.1`，回环地址不经过防火墙；
或者按端口放行一次（管理员 PowerShell），之后 exe 在哪都不再问 —— 网页是 TCP，节点广播是 UDP 7865：

```powershell
netsh advfirewall firewall add rule name="lannav web"  dir=in action=allow protocol=TCP localport=7865 profile=private,public
netsh advfirewall firewall add rule name="lannav peer" dir=in action=allow protocol=UDP localport=7865 profile=private,public
```

在源码目录下运行时，改 `data/data.json` 或主题文件后**刷新即生效**，不用重启：
每次请求都重新读数据和模板。只有改了 `.go` 文件才要重新编译。

## 目录

```
main.go              入口：解析参数、go:embed 主题、把下面几个包接起来
internal/
  theme/             主题从磁盘读还是用内置的
  store/             data.json 的模型、读取、排序过滤、校验、原子写回
  server/            路由、导航页、编辑页、保存接口、「发现的服务」
  scan/              端口扫描：探一个地址上开着的服务，以及扫描结果的内存缓存
  peer/              节点：别的机器也跑着导航页时直接问它要端口，不扫（独立，可整个删掉）
  listen/            读本机的 TCP 监听表（Windows：GetExtendedTcpTable，Linux：/proc/net/tcp），本机不用扫
go.mod               无依赖
data/
  data.json          全部内容（运行时读取，不嵌进二进制）
themes/              //go:embed 进二进制，磁盘上有同名目录时优先用磁盘
  default/
    index.html       导航页模板
    styles.css       全部外观
    app.js           搜索、快捷键、深浅色、时钟
    admin.html       编辑页模板
    admin.css        编辑控件样式
    admin.js         编辑页行为
```

**换主题就是复制 `themes/default` 改一个名字**，然后 `.\lannav.exe -theme 新名字`。
主题目录下的文件通过 `/static/` 提供，模板里写 `/static/styles.css` 即可，不用改 Go 代码。

### 主题从哪来：磁盘优先，内置兜底

`themes/` 整个被 `//go:embed` 编译进二进制，但启动时会先看磁盘：

```
磁盘上有 themes/<主题>/index.html ？
  有  → 用磁盘（启动日志显示「磁盘」）—— 改模板/样式刷新即生效
  没有 → 用嵌进二进制的那份（显示「内置」）
```

这样一份代码同时满足两种场景：源码目录下开发时改完就看得见；
把编译好的二进制单独拷到别处跑，身边没有 `themes/`，自动用内置的。

想在已部署的机器上临时改点样式，就在二进制旁边放一个 `themes/default/`，
它会盖掉内置的那份；删掉就回到内置版本。

`data/data.json` **不嵌**。它是运行时配置，嵌进去就失去「改完刷新生效」的意义，
也就没法用编辑页改了。

## 分组与路由

| URL | 行为 |
|---|---|
| `/` | 从第一个分组开始 |
| `/dev` | 打开后滚到 id 为 `dev` 的分组 |
| `/services` | 「发现的服务」（设了扫描地址才有；这个 id 普通分组不能用） |
| `/admin` | 编辑页 |
| `/不存在` | 404 |

**所有分组都渲染进同一个页面，从上到下排开。** 服务端只在侧边栏里给 URL 对应的那一项标上
`aria-current`，页面加载后 app.js 按地址栏滚到那一组。所以搜索能跨分组命中（下一节）。
代价是页面体积等于全部书签。几百条书签也就几十 KB，值得。

点侧边栏**不回服务端**：`scrollIntoView` 滚到那一组，再 `history.pushState` 改地址栏。
分组标题是 sticky 的，滚到哪一组，哪一组的名字贴在顶栏下面。侧边栏跟着这个标题走：
贴顶标题还完整露在顶栏下面的第一个分组算「当前」，上一组的标题一开始被顶出去就切到下一组，
侧边栏亮的永远是眼前看到的那个标题。地址栏用 `replaceState` 同步（滚动不产生历史记录）。
服务端路由依然保留，直接输入地址、刷新、以及禁用 JS 时都是整页从头显示。

### 跟着当前地址走的书签

书签的链接写成 `:8080/test` 这种冒号开头的形式，点开时会补成
**你此刻访问这个导航页用的那个地址** + 这个端口和路径：

| 你从哪打开导航页 | `:8080/test` 实际点到哪 |
|---|---|
| `http://localhost:7865/` | `http://localhost:8080/test` |
| `http://10.0.0.9:7865/` | `http://10.0.0.9:8080/test` |
| `http://nas.local/` | `http://nas.local:8080/test` |

内网服务的书签写死一个 IP，换个网段、或者掏出手机打开就点不开了。
写成 `:8080`，同一份 `data.json` 从哪台机器上看都指得对。

**补全在服务端做**，用的是这次请求的 `Host` 头 —— 也就是你地址栏里主机那一截。
只有服务端每次请求才知道这回是从哪个地址进来的。页面渲染出来就是真地址，
不依赖 JS，搜索（按域名匹配）和「在新标签页打开」都照常。

几种写法：

| 写法 | 结果 |
|---|---|
| `:8080` / `:8080/test` | 当前主机 + 这个端口 |
| `/test` | 当前主机**和当前端口** + 这个路径（浏览器本来就会补，服务端不碰） |
| `https://…`、`mailto:…` | 原样不动 |

冒号后面必须是 1–65535 的端口号。`:abc` 这种保存时就被退回来 ——
拼出来的地址点不开，与其存进去变成死链，不如当场拦住。

编辑页的链接框因此不能用 `type="url"`（它不收冒号开头的写法），改成了 `pattern`。

### 关于闪烁

两处容易踩的坑，都已经处理：

- **深色模式白闪**：主题初始值必须在首次绘制前定好，所以那段代码内联在
  `index.html` 的 `<head>` 里、排在样式表之前。搬进 `app.js` 或任何外部文件都会重新闪。
- **整页导航**：见上，切分组不再重新加载文档。

页面没有 favicon，`/favicon.ico` 返回 404。因为切分组不再产生新文档，
这个请求只在首次加载时发生一次。
## 搜索

`themes/default/app.js` 里一个循环：

```js
a.hidden = q !== "" && !(a.hostname + a.textContent).toLowerCase().includes(q)
```

- **匹配范围**：链接域名 + 卡片上的可见文字（名称、描述、图标）
- **不需要任何预计算属性**，名称和描述本来就渲染在卡片里
- **不需要搜索库**，几百个条目每次按键 1 毫秒内完成

搜索时 `<body>` 挂上 `data-searching`，CSS 用 `:has()` 把没有命中项的分组整组收起，
清空输入框就全部放回来。分组显隐全在 CSS 里，JS 只负责给卡片设 `hidden`，
并给第一条命中项挂 `data-first`：它描上强调色边，回车打开的也是它。
空状态的文案由 JS 写进 `<p class="empty" role="status">`：读屏只在文本真正变化时
播报，纯 CSS 的显隐它听不见；写空字符串则命中 `.empty:empty` 自动收起。

想让某个字段可搜，就把它渲染成卡片上的可见文字，不要回头加属性。

### 键盘

| 键 | 行为 |
|---|---|
| 任意可打印字符 | 焦点不在输入框时，聚焦搜索框并把这个字符输进去（空格除外，留给翻页） |
| `/` | 聚焦搜索框，不输入斜杠 |
| `Esc` | 清空搜索 |
| `Enter` | 打开第一条命中项（描了边的那张） |

桌面宽度下页面一打开焦点就在搜索框里，中文输入法从第一个字母起就是拼音；
窄屏不自动聚焦，免得软键盘一上来盖住卡片。

## 编辑页 /admin

`http://localhost:7865/admin` 是一个表单版的 data.json：每条书签一行，
改完点「保存到 JSON」（或按 `Ctrl+S`，Mac 上 `⌘S`）写回磁盘。导航页刷新即生效。
按 `Esc` 等于点「放弃改动」：有改动时先确认再重新读取；扫描对话框开着时 Esc 只关对话框。

```
┌───────────────┬────────────────────────────────────────────────┐
│ 编辑书签       │ 站点标题[我的导航]   ●保存到 JSON  放弃改动  ◐ │
│               ├────────────────────────────────────────────────┤
│ 💻 开发     4 │ [💻][开发      ] id[dev  ] □隐藏整组  ↑ ↓ 🗑    │
│ 🧰 常用工具 3 │ ───────────────────────────────────────────────│
│ 🎬 影音     2 │ [🐙][GitHub  ][https://github.com ][代码托管]  │
│ 🏠 内网服务 2 │                            □隐藏   ↑ ↓ 🗑      │
│               │ ＋ 新增书签                                    │
│ ＋ 新增分组    │                                                │
│ ← 回到导航页   │                                                │
└───────────────┴────────────────────────────────────────────────┘
```

**排序用 ↑ ↓ 按钮，不做拖拽。** 按钮天然是键盘可用的，拖拽还得额外再配一套
键盘方案。`order` 字段不用手填也不从页面提交 —— 保存时服务端按行的先后重新编号，
顺带把手改 JSON 时留下的跳号、重号抹平。

编辑页看得到 `hidden: true` 的条目（导航页看不到），所以隐藏和取消隐藏都在这里做。

**链接打开方式**：顶栏「链接打开方式」是全站默认（新标签页 / 当前页），每条书签行里还有一个
下拉，默认「跟随默认」，只有这一条想跟大家不一样时才改它。「发现的服务」里的卡片一律跟随全站。
没设过的旧 `data.json` 全部新标签页打开，跟加这个选项之前一样。

### 保存这条路

```
浏览器 ──POST /api/data──► 校验 ──► 比对文件指纹 ──► 备份 ──► 临时文件 ──► rename
         整份文档 + 指纹      ↓ 不过         ↓ 对不上
                          400 原样退回   409 「文件被改过，请刷新」
```

- **整份提交**，没有单条增删接口。文件才几十 KB，省掉一整套 id 管理和并发合并逻辑。
- **校验不过整份拒绝**：分组 id 必须是 ASCII 且唯一、名称和链接不能空。
  绝不会写进去半份数据。前端先跑一遍浏览器原生校验（`required` 和 `pattern`），
  错的字段自己高亮，不另写一套提示。
- **文件指纹**（改动时间 + 大小）随页面下发、随保存带回。你在编辑期间手改过
  `data.json` 的话，保存会被 409 挡住，不会静默覆盖掉那边的改动。
- **原子替换**：先写 `data.json.tmp` 再 `rename`。中途崩溃最多留下一个 `.tmp`，
  不会把 `data.json` 截成半个 JSON。
- **每次保存前留一份 `data.json.bak`**（上一版的原样字节）。改坏了直接改名回去。

### 编辑页的文件

```
themes/default/
  admin.html   模板：一行书签的结构用 {{define "row"}} 只写一次，
               已有行和「新增」用的空白行都从它生成
  admin.js     切分组、增删移动、把 DOM 拼回 JSON、提交
  admin.css    只有编辑控件的样式；配色、焦点环、侧边栏复用 styles.css
```

页面上的输入框就是唯一的真相，JS 里没有任何数据副本，保存时现场读一遍 DOM。

### 保存后另一个标签页自动刷新

编辑页保存成功后广播一条 `BroadcastChannel("nav")`，导航页收到就 `location.reload()`。
两行，零 Go 代码，零请求。

跨标签页只能传消息、不能直接操控对方，所以是「广播一声让它自己刷」而不是
「我去刷它」—— 浏览器没有后者那种 API。

**只在同一个浏览器内有效**，广播走的是浏览器进程内部，不过网络，手机上开着的那个
标签页收不到。真要覆盖手机，就得让导航页在 `pageshow` / `visibilitychange` 时
去比对一次文件指纹（服务端 `store.Raw()` 已经在算了），约八行。现在没做。

（另外：服务端每次请求都重读 `data.json`，所以手动刷新任何时候都是最新的。
这条广播只是省掉「手动」两个字。）

**没有访问控制**：`/admin` 和写接口一直开着。自己机器上跑没问题，但这个服务
监听的是所有网卡 —— 局域网里任何人都能改你的 `data.json`。要挂到内网或公网之前
先加限制。
`/api/scan` 也一样开着：能打开 `/admin` 的人，就能借这台机器去扫任意地址的端口。
限制访问时这个接口和写接口一起考虑，别只挡住 `/admin` 页面。
`/api/services/refresh` 只扫 `data.json` 里设好的地址，但任何能打开导航页的人都能触发一轮扫描。
`/api/ports` 谁都能问，报的是这台机器开着的服务（内容本来就是局域网里扫一下能看到的东西）；
不想被查就加 `-peer=false`。

## 发现的服务

导航页左侧书签分组下面的「📡 发现的服务」：把编辑页里设好的几个地址扫一遍，
开着的网页服务直接列成卡片。和普通分组渲染在同一个页面里，路径是 `/services`，搜索照样搜得到。

```
编辑页「发现的服务」面板 ──保存──► data.json 的 "scan"
                                        │ 点刷新时现读
导航页「刷新」──POST /api/services/refresh──► 扫一轮 ──► 存进内存 ──► 204 ──► 页面重载
```

- **本机不扫，读监听表。** 设置里的地址是本机（`localhost`、`127.0.0.1`、`::1` 或本机网卡上的 IP）时，
  直接读系统的 TCP 监听表（`netstat`/`ss` 读的就是它），只对设好的端口范围里真在监听、从这个地址连得上的
  那几个发 HTTP 请求取名字，不去挨个拨关着的端口。Windows 和 Linux 支持；别的系统（如 macOS）退回扫描。
  编辑页的扫描对话框扫本机时也一样。
- **启动时先看一眼本机。** 程序一启动就在后台把本机的地址过一遍，第一次打开就有结果。
  别的机器启动时不碰 —— 一启动就自己拨一大片端口，会被 Windows Defender 当成扫描器报毒 ——
  那一栏会提示「还没扫，点刷新」。之后不定时刷新，结果只存在服务端内存里（重启就没了，
  端口开没开本来就是会变的东西）。设置里没有本机地址时，第一次打开显示「还没扫描过」。
- **设置在编辑页改。** 侧边栏「发现的服务」打开设置面板：地址一行一个（最多 16 个），
  端口写法同扫描对话框（每个地址最多 4000 个，地址数 × 端口数最多 20000）。跟书签一起点「保存到 JSON」才生效。
  地址留空，导航页上就不出现这一栏。
- **设置是点刷新那一刻现读的**，改完保存不用重启。设置改过而结果还是旧的，那一栏会提示一句。
- **同时只扫一轮。** 连点两下、或者两个页面同时点，第二个请求等着同一轮扫完，不会再开一轮。
  扫描挂在后台，点完刷新关掉页面也会扫完，下次打开就是新结果。
- **只列网页服务。** SSH、数据库这类开着但不是网页的，只在那一栏的说明里报个数。
  名字和描述的取法跟扫描对话框一致；扫的是本机时链接存成 `:端口`，跟着你访问导航页的地址走。

```jsonc
"scan": {
  "hosts": ["192.168.1.10", "nas.local"],
  "ports": "80,443,8000-8100"
}
```

## 节点

内网里另一台机器也跑着这个导航页（叫它「节点」）时，不扫它：直接问它的 `GET /api/ports`，
它读自己的监听表把开着的服务报回来。「发现的服务」和编辑页的扫描对话框都是这样：

```
是本机？ ──是──► 读监听表
   │否
问 地址:7865/api/ports，不通再问 :80 ──是节点──► 用它报的端口（卡片上标「导航页节点」）
   │不是
照常扫描
```

- **问哪些端口**写在 `internal/peer/node.go` 的 `NodePorts`（现在是 `7865, 80`），改策略只改这一行。
- **启动时**也会问一下设置里那些不是本机的地址（每个就一两个 HTTP 请求，不扫描），是节点的直接有结果。
- **查找节点**：编辑页「发现的服务」面板里两个按钮，找到的点「加入」写进地址框，保存后生效。
  - 「查找节点」往每张网卡的本网段发 UDP 广播（端口 7865，`peer.UDPPort`），等 1 秒收回话。
    只在同一网段有效；节点要放行入站 UDP 7865，第一次运行时 Windows 会弹窗问。
  - 「逐个询问网段」是广播不通时的备用：把本机所在 /24 的每个 IP 按 `NodePorts` 问一遍，并发 16，十几秒。
    也是批量连接，所以只在点按钮时做。
- **`-peer=false`**：不回答别人的 `/api/ports` 和广播，这台机器不被发现、不被查询（自己照样能去找别人）。
- 节点网页端口不在 `NodePorts` 里（比如 `-port 9000`）时，广播能找到它，但加进地址后问不到，会按普通地址扫描。
- 节点只报自己的端口，不会再去问别的节点。导航页跑在 Docker 里时报的是容器自己的端口（除非 `--network host`）。

**删掉这个功能**：删 `internal/peer`、`main.go` 里标了的那几行、`themes/default/peer.js`、
`admin.html` 里「查找节点」那一块和 `admin.css` 末尾一节。`scan.Ask` 钩子留着是 nil，照常扫描。

## 扫描服务

内网自建的东西多半没人记得住端口。编辑页侧边栏的「扫描服务」给一个地址，
把上面开着的端口找出来、顺手认一下是什么，勾中的直接变成当前分组里的书签行。

```
┌─ 扫描服务 ─────────────────────────────────── ✕ ┐
│ 地址[192.168.1.10]  端口[80,443,8096,…]  开始扫描│
│ 扫了 24 个端口，开着 3 个                        │
│ ☑ 80    OpenWrt                                  │
│         http://192.168.1.10:80        nginx      │
│ ☑ 8096  Jellyfin                                 │
│         http://192.168.1.10:8096                 │
│ ☐ 22    SSH                                      │
│         http://192.168.1.10:22      非网页服务   │
│ 勾中的会加到当前分组          [加入当前分组]     │
└──────────────────────────────────────────────────┘
```

### 怎么探的

1. **TCP 拨一下**（600ms 超时）看端口开不开。关着的不出现在结果里。
2. 开着的再**当 HTTP 请求一次**（2s 超时），从 `<title>` 拿名字。
   先试 `http://`，连不上或者撞见「plain HTTP request was sent to HTTPS port」
   就改 `https://` 再来一次 —— 内网两种都常见，让人自己先选协议太啰嗦。
   证书一律不校验（自签名是常态）。重定向**只跟「只换路径」的那种**：Jellyfin、
   Grafana 这类首页本来就是 302 到 `/web/`、`/login`，不跟过去就拿不到名字。
   换了主机、端口或协议就停下：那边的标题不是这个端口的，而且 `github.com:80`
   那种「跳去 https 但端口还写着 80」跟过去只会拿明文去敲 TLS，白白把一个
   301 变成「探测失败」。真的 https 由上面第 2 步自己再试一遍。

名字按 `<title>` → 常用端口名表（22 SSH、3306 MySQL、32400 Plex…）→ `地址:端口`
逐级退。描述栏填 `Server` 头和非 200 的状态码 —— 401 也算找到了，只是要登录。
页面不是 UTF-8 时（老设备常回 GBK）宁可不显示标题，也不往 `data.json` 里塞乱码。

**默认勾中的，是网页、而且还没在书签里的那些。** SSH、数据库这类不勾：
导航页放的是能点开的链接。URL 已经在书签里的也不勾，省得加重复的。

### 端口怎么写

`80,443` 或者 `8000-8100`，混着写也行，重复的会去掉。一个地址一次最多 4000 个，
超了直接 400 —— 「一轮扫完一次性回一包 JSON」能成立就靠这条。

**上限怎么来的。** 用时取决于关着的端口怎么回：

| 目标 | 2526 个端口实测（256 并发） | 原因 |
|---|---|---|
| `127.0.0.1` | 不到 0.1s | 回环上关着的端口立刻拒绝 |
| 本机的局域网 IP | 6.0s | Windows 在网卡上被拒绝后还要重试两次，2s 才报错，每个都等满 600ms 超时 |
| 不存在 / 防火墙丢包的地址 | 同上 | 每个都等满超时 |

最坏情况 ≈ ⌈端口数 ÷ 256 并发⌉ × 0.6s。4000 个端口最坏 10s 左右。
瓶颈是干等超时，不是网卡：同样 2526 个端口，并发 128 / 256 / 512 分别是 12s / 6s / 3s，找到的端口一样。
没用 512 是因为那样编出来的程序会被 Windows Defender 误报成病毒、直接隔离（实测必现，256 和 128 不会）。
「发现的服务」几个地址共用同一个并发池，所以另有一道 **地址数 × 端口数 ≤ 20000**
（最坏约 47s，留在刷新 3 分钟总时限以内，免得超时那一刻没扫到的端口被悄悄漏掉）。

**扫得多的代价**，除了慢：

- 开着的端口每个还要发一两次 HTTP 请求（最多各等 2s）。Redis、MySQL 这类非网页服务
  收到 HTTP 请求会在自己的日志里记一笔「可疑请求」。
- 在公司或别人的网络上，大范围扫端口可能触发入侵检测、被网管找上门。只扫自己的机器和自己的设备。
- 卡片会变多：开发时随手起的临时服务也会被扫进来。

没有「最佳数量」，取舍是等待时间：能接受等 W 秒，最坏情况下一个地址大约能扫 W ÷ 0.6 × 256 个端口
（6 秒 ≈ 2500，10 秒 ≈ 4000）。扫本机 `127.0.0.1` 几乎不花时间，范围放宽也无所谓。扫本机 `127.0.0.1` 几乎不花时间，范围放宽也无所谓。

默认那串端口写在 `admin.html` 的 `<input value="…">` 里，不在 Go 代码里：
它是这套界面的默认值，换主题就该能跟着换。

关掉对话框会把还在飞的那轮掐掉：浏览器 `AbortController` 断开连接，
服务端挂在请求 context 上的探测立刻收手，不会在后台慢慢超时。

### 地址框的 placeholder 是本机 IP

地址框空着的时候显示的是**这台机器自己的局域网 IP**（比如 `10.0.0.9`），
服务端渲染编辑页时算出来填进 `placeholder`。要扫的多半就是本机或者同网段的
邻居，这样不用先去翻一遍 `ipconfig` 才知道自己在哪个网段。

算法是往 `192.0.2.1`（RFC 5737 留给文档用的网段，不会是真机器）**拨一个 UDP**。
UDP 的 connect 不发任何包，只是让系统按默认路由挑一张网卡、绑一个本地地址，
拨完就关。之所以不直接翻网卡列表：一台机器上 VPN、WSL、Docker、蓝牙各占一张，
列表里第一个「看着像内网」的常常不是真正上网那张 —— 按默认路由挑不会认错。

没有默认路由（离线）就退回翻网卡找私网 IPv4。再认不出来就返回**空串**，
不编一个看着像模像样的 IP —— 下一节要拿这个值判断「扫的是不是本机」，编出来的会被当真。
格式示例（`192.168.1.10`）那时由 `admin.js` 兜上。

placeholder 只是提示，**不会被当成默认值**：空着点扫描照样拦住。

### 扫的是本机，就存成 `:端口`

扫的要是**跑着这个导航页的那台机器**，加进来的书签存的是 `:8096` 而不是
`http://10.0.0.9:8096` —— 也就是上面「跟着当前地址走的书签」那种写法。
在机器上扫出来的服务，跟导航页本来就同一台，写死 IP 纯属自找麻烦。
对话框底下会说一声，不会悄悄改。

算「本机」的有三类，都确确实实是这台机器：

| | 为什么算 |
|---|---|
| 和地址栏里的主机一样 | 你此刻就是用它打开的这个页面，它必然通到这个服务 |
| 和 placeholder 一样 | 服务端自己算出来的局域网 IP（认不出来是空串，匹配不上谁） |
| `localhost` / `127.0.0.1` / `::1` | 扫描是**服务端**发起的，回环说的就是服务端自己 |

只对 `http://` 这么存。`:端口` 补出来的是 http，把一个 https 服务写成这样
等于把协议弄丢了，那种老老实实存绝对地址。

**名字也一样。** 服务连 `<title>` 都没有、又不在端口名表里时，书签名退回拿地址当名字 ——
本机的话这里同样用 `:8098`，不然链接跟着地址走、名字却写死一个 IP，换台机器看就对不上了。

已经以 `:8096` 存过的，再扫一遍也认得出来，默认不再勾。

### 扫出来的东西不会自己落盘

「加入当前分组」只是往页面上添几行，和手打的一模一样，要点「保存到 JSON」
才写进 `data.json`。扫错了点「放弃改动」就没了。

## 外观约定

改主题时这几条建议保留，它们是可用性而不是品味：

- **焦点环**：`--focus` 一个变量管住侧边栏、卡片、按钮三处 `:focus-visible`。
  移动端侧边栏是横向滚动的，外发光会被裁掉，所以那里换成 `outline-offset: -2px` 内描边。
- **图标分两类**：`data.json` 里的 emoji 是内容，旁边就有名称，所以标了 `aria-hidden`；
  深浅色按钮这种结构性图标用内联 SVG（`currentColor`、尺寸固定），不用字符或 emoji。
- **顶栏和侧边栏常驻**（sticky），搜索和分组在任何滚动位置都伸手可及。
  配套的 `scroll-padding-top` 不能删，否则 Tab 到卡片时会被顶栏挡住。
- **可点区域最小 40px**，深浅色按钮、侧边栏条目、搜索框都按这个高度走。
- **描述一行到底，超出用省略号**；完整文本放在 `title` 上，悬停可见，不至于永久藏住。
- **`prefers-reduced-motion`** 下取消过渡和悬停位移，状态变化改由颜色表达。
- **对比度**：浅色下 `--muted` 对白底 5.7:1、对页面底色 5.3:1，深色下对面板 6.2:1，都过 4.5:1。
  换配色时这一项要重新量，不能靠「深色看着还行」。

## data.json

```jsonc
{
  "title": "我的导航",
  "open": "tab",           // 可选，链接默认怎么打开："tab" 新标签页（默认）/ "self" 当前页
  "groups": [
    {
      "id": "dev",          // URL 用，必须是 ASCII
      "name": "开发",        // 侧边栏和标题显示
      "icon": "💻",          // 可选，默认 📁
      "order": 1,           // 可选，越小越靠前
      "hidden": false,      // 可选，true 则整组不渲染
      "items": [
        {
          "name": "GitHub",
          "url": "https://github.com",   // 也可以写 ":8080/path"，见「跟着当前地址走的书签」
          "open": "self",                // 可选，单条覆盖全站的打开方式；不写就跟随全站
          "description": "代码托管",  // 可选
          "icon": "🐙",              // 可选，默认 🔗
          "order": 1,                // 可选
          "hidden": false            // 可选
        }
      ]
    }
  ]
}
```

`hidden` 过滤和 `order` 排序都在 Go 里做完，模板不含任何逻辑。

## 部署

```bash
go build -o lannav .
```

拷两样东西到目标机器：

```
lannav（或 lannav.exe）    约 13 MB，主题已经在里面
data/data.json      你的书签
```

没了。不需要 `themes/`、不需要运行时、不需要任何依赖。

交叉编译到 NAS / 树莓派也是一条命令：

```bash
GOOS=linux GOARCH=amd64 go build -o lannav .      # x86 NAS
GOOS=linux GOARCH=arm64 go build -o lannav .      # 树莓派、ARM NAS
```

`data/` 下面还会出现两个文件，都是编辑页保存时产生的：
`data.json.bak`（上一版的原样字节，改坏了直接改名回去）和写入过程中一闪而过的
`data.json.tmp`。
